# Contract Intelligence Assistant — evaluation report

All numbers below are read from files under `experiments/` (generated by the commands in "Reproducibility"). Measured
results and hypotheses are labelled separately.

## 1. Summary

**What was built.** A fully offline retrieval system (BM25 + TF-IDF, no LLM) that, for a natural-language question about the 29
contracts referenced by the LegalBench-RAG-mini CUAD queries, returns ranked passages with file path, exact character offsets and the
exact source substring, or abstains. It ships a CLI, a Streamlit app (same service layer), 194 passing tests, typed YAML configs, a frozen
unanswerable-question set (39 queries), official-style character precision/recall, abstention metrics in both directions, failure diagnostics,
and a train-only self-improvement loop with an append-only log.

**Headline held-out test results** (54 answerable + 6 unanswerable test queries; final config evaluated once; macro averages):

| Metric (test split) | Baseline | Final |
|---|---|---|
| Char Recall@5 / Precision@5 | 0.136 / 0.0085 | **0.655 / 0.049** |
| Char Recall@1 / Precision@1 | 0.019 / 0.003 | 0.469 / 0.131 |
| Answerable coverage (not abstained) | 54/54 = 1.00 | 49/54 = 0.907 |
| Correct abstention on unanswerable | 0/6 | 3/6 = 0.50 |
| False acceptance on unanswerable | 6/6 | 3/6 = 0.50 |

Reading these honestly: recall is decent, **precision is low** (a 1500-character chunk and five passages against gold spans averaging ~400
characters), and the 6-query unanswerable test sample is far too small for a confident abstention estimate (0.50 on n=6 has a very wide interval).

## 2. System design

Data flow: manifest (29 allowed contracts) → original text (`Path.read_text(encoding="utf-8")`, never altered) → chunks as `[start,end)` intervals of
that text → inverted index → candidates → overlap suppression → abstention decision → result with `text = document[start:end]`.

| Decision | Choice | Alternatives considered |
|---|---|---|
| Retriever | Own pure-Python BM25 (Lucene idf) + TF-IDF cosine fused with RRF | `rank-bm25` (extra dep, no OOV-aware normaliser); dense + FAISS (heavy, not needed for a first honest baseline; not tried) |
| Chunking | Fixed 1500-char windows (strategy chosen by the loop) | Paragraph and section-aware packing were implemented and tested; both scored worse on train (§5) |
| Query handling | Strip the `Consider the <contract>;` prefix for chunk scoring, keep a document-level BM25 prior (weight 1.0) from the *full* query for routing, stemming, stopwords, hand-written lexicon expansion | Stripping *without* the document prior collapsed recall (Run 1) |
| Abstention | Threshold 0.68 on "document peakedness": (best literal-question match − median chunk) / best, in the routed contract | Normalised BM25 (AUC 0.21–0.56 on train: dominated by query length/expansion), top-2 gap (no gain) |
| Offsets | Chunks are never re-assembled; trimming only shrinks bounds; tests cover Unicode, CRLF, empty/whitespace docs, all strategies | — |

**LLM use.** None. No LLM, embedding model or hosted API is used anywhere (reasons: offline reproducibility, contract privacy, nothing to cache or
pay for, and the deadline). The *development* of this repository was done with Claude Code (see README "AI tool usage").

## 3. Evaluation setup

* **Data:** CUAD subset of `awinml/legalbench-rag` (`benchmarks/cuad.json`: 4,042 tests). `mini()` implemented verbatim → **194 queries**, **272 gold
  spans**, **29 contracts** (the only ones indexed). All 272 spans validated (`document[start:end] == answer`): **0 invalid, 0 overlapping gold pairs, 0 skipped records**.
  Manifest hash `e2a5024fd7e7ef0b`.
* **Split:** `assign_split` verbatim: **140 train / 54 test** answerable.
* **Unanswerable set:** 39 original questions in `data/unanswerable_queries.jsonl`, split by the same function: **33 train / 6 test** (not forced to a third).
  Frozen in commit `f5b73f4` before any retrieval code existed; sha-256 asserted by a test.
* **Metrics:** per-query character precision/recall following the official `run_benchmark.py` convention (overlap with gold in the same file; precision 0 if nothing
  is returned; macro mean over queries). Deviation (documented in `metrics.py`): retrieved and gold intervals are merged to unions so duplicates/overlaps are never
  double-counted (identical to the reference when results do not overlap). Abstained answerable queries score 0 (they are in the denominator). Supplementary: document hit, span hit, MRR, micro precision/recall.
  Abstention: coverage = answered/answerable; correct abstention = abstained/unanswerable; false acceptance = answered/unanswerable (numerators and denominators reported).
* **Test evaluations performed: 2** (`experiments/final_test_runs.jsonl`): final config (run 1) and baseline (run 2), both after the config freeze (tag `config-frozen`); no test result influenced any decision.

## 5. Optimization: objective, loop, iteration history

**Objective (frozen before tuning, revisions logged in `docs/optimization_objective.md`).** Phase A: maximise macro char Recall@5 with abstention disabled on the 140 train answerable queries,
guardrails: Precision@5 ≥ 0.90×baseline (0.0167), latency ≤ min(5×baseline, 500 ms), chunks ≤ 10×baseline; accept only if Recall@5 improves by > 0.002.
Phase B: maximise correct-abstention on the 33 train unanswerable queries at the highest threshold keeping answerable coverage ≥ 0.90 (rule R), without losing > 0.002 of Recall@5/Precision@5; accept if gain > 0.02.
Each iteration evaluates a small grid for one hypothesis, takes the best guardrail-passing point, and logs everything (`experiments/iterations.jsonl`, 45 rows over 4 runs).

**Run 4 (the run that produced `configs/final.yaml`; 10 iterations, ~35 s total):**

| # | Hypothesis | Best grid point | Obj. before → after | P@5 after | Decision |
|---|---|---|---|---|---|
| 1 | structure-aware chunks | section | R@5 0.190 → 0.105 | 0.0120 | **rejected** (both options violate precision guardrail) |
| 2 | chunk size | 1500 | 0.190 → 0.268 | 0.0196 | **accepted** (2500 had R@5 0.395 but P@5 0.0166 < 0.0167 limit → guardrail-rejected) |
| 3 | overlap / boundary snapping | overlap 100 | 0.268 → 0.261 | 0.0175 | rejected (worse) |
| 4 | strip descriptor + document prior + stemming | boost 1.0 + stem | 0.268 → 0.394 | 0.0282 | **accepted** |
| 5 | query expansion lexicon (+ stopwords) | expand + stopwords | 0.394 → 0.717 | 0.0501 | **accepted** |
| 6 | BM25 k1/b | k1 2.0, b 0.5 | 0.7169 → 0.7170 | 0.0502 | rejected (+0.0001 < 0.002) |
| 7 | RRF fusion with TF-IDF | rrf_k 60 | 0.7169 → 0.7195 | 0.0498 | **accepted** (+0.0026, marginal) |
| 8 | topical-term confidence | min 3 contracts | correct-abstention 0.00 → 0.061 | 0.0498 | **accepted** (2/33) |
| 9 | peakedness confidence | peakedness | 0.061 → **0.545** | 0.0498 | **accepted** (18/33, threshold 0.68, coverage 0.90) |
| 10 | top-1/top-2 gap policy | min_gap 0.05 | 0.545 → 0.545 | 0.0498 | rejected (no gain) |

The query-expansion step is the largest single gain (R@5 +0.32 on train). It rests on a hand-written lexicon (`lexicon.py`) written from general contract knowledge and the *question templates*
visible in train (all 140 train queries are one of only 30 distinct templated questions); it never used gold spans, but it encodes CUAD-style categories and may transfer less to differently phrased questions.

**Earlier runs (kept in the log; I changed the code between runs, so these are not independent trials):**
* *Run 1 (`20261029T175554Z`)*: first 9 hypotheses. Accepted chunk size 1500 and k1/b (R@5 0.190 → 0.2745); stripping the descriptor alone *hurt* (0.113) because it removed contract routing; topical confidence 0.21 → 0.36 correct abstention; gap policy was spuriously rejected by a bug (negative gap).
* *Run 2 (`...175827Z`)*: after fixing the gap bug and adding document-prior/expansion hypotheses, R@5 reached 0.7195, but every abstention candidate failed (correct abstention 0.0) — traced to two signal defects (abstaining on zero confidence even with threshold 0; unseen query terms ignored by the normaliser).
* *Run 3 (`...180030Z`)*: after those fixes, topical confidence 0.0 → 0.06; the run **crashed** in iteration 10 (division by zero in the gap path, now fixed); no `finalize` row.
* *Run 4*: above, after adding the `doc_peakedness` signal motivated by a train-only AUC diagnostic.

Consequence worth stating: I observed train results and then changed hypotheses and code three times, so the "train" numbers reflect more researcher degrees of freedom than the single-pass protocol suggests. The held-out test split was never consulted until after the freeze.

## 6. Error analysis (16 observed failures of the final config; `experiments/results/final_*_per_query.jsonl`)

Failure categories at k=5, final config — train (n=140 answerable): wrong document 10, right document/wrong section 20, incomplete coverage 4, **overly broad 91**, false abstention 14, success 1; test (n=54): wrong document 5, wrong section 6, incomplete 2, overly broad 34, false abstention 5, success 2.
("Success" requires recall ≥ 0.5 **and** precision ≥ 0.25, which 1500-char chunks almost never meet; the dominant failure is therefore that the right clause is found inside a much longer passage.)
The diagnostic tag `query_wording_mismatch` fires for 97-99% of answerable queries (138/140 train, 52/54 test) (templated questions share almost no words with gold clauses), so it is not informative.

**A. Wrong contract (3)**
1. `cuad-c3e0e0f9d2` (train) — BicycleTX service agreement, "right of first refusal/offer/negotiation?". Gold (6235–6531) is a share-option grant; retrieved: a Joint-Venture agreement's transition-services text (Igene). Diagnosis: generic "first/negotiation" vocabulary in another contract outscored the document prior; the gold clause itself has little lexical link to the question (annotation looks loose).
2. `cuad-4228f7e817` (train) — HPIL cooperation agreement, anti-assignment. Gold: "shall not be assignable by any Party" (17341–17432); retrieved King Pharmaceuticals §16.8 "Successors and Assigns". Diagnosis: short clause vs a longer boilerplate chunk with more `assign*` matches; routing prior (weight 1.0) too weak against a chunk score ≈ 1.0.
3. `cuad-5febc1f161` (train) — Cano/Boyd sponsorship, "expiration date?". Gold: "The term ... shall be one (1) year ... ending on December 31, 2008." Retrieved: Papa John's expiration/termination text. Diagnosis: the stemmer maps "expiration"→"expir" but "expire"→"expire", and the clause says "term"/"ending", not "expiration".

**B. Right contract, wrong section (3)**
4. `cuad-4898a9bce3` (train) — Theravance service agreement, "terminated for convenience?". Gold: employer may terminate "in its sole and absolute discretion ... immediately" (18678–18997); retrieved the list of for-cause grounds (§18.1.x, 21000–22500). Diagnosis: same vocabulary ("terminate", "notice") in neighbouring termination clauses.
5. `cuad-1a6adb98b6` (train) — same contract, "covenant not to sue?". Gold text is about termination on reconstruction/amalgamation; retrieved a confidentiality chunk. Diagnosis: no lexical bridge; likely loose CUAD labelling — cannot be fixed lexically.
6. `cuad-b1f8efd953` (train) — Flotek supply agreement, "duration of any warranties?". Gold (3021–3209) is purchase-order acceptance within three days; retrieved inventory/price text. Diagnosis: gold seems unrelated to warranties; probable label mismatch (not verified against the CUAD source).

**C. Incomplete gold coverage (2)**
7. `cuad-03914e2684` (train) — BicycleTX IP assignment. Gold 44840–45359; retrieved chunk 43501–45000 ends mid-clause (R@5 0.308). Diagnosis: fixed windows cut the clause at 45000 (overlap/snap were tested and rejected on train).
8. `cuad-494a099d52` (train) — HPIL "cap on liability?". Gold has two spans (11380–11583, 12564–12768); the top chunk covers the first only (R@5 0.499); the other four passages come from unrelated contracts. Diagnosis: multi-span answers need adjacent chunks; the result list is not restricted to the routed contract.

**D. Overly broad (2)**
9. `cuad-6c037bc6cb` (train) — Theravance IP ownership. Chunk 16500–17999 contains the 302-char gold (recall 1.0) but precision@5 is 0.040.
10. `cuad-6d5b80b018` (train) — Cano anti-assignment. Chunk 6001–7500 contains the 104-char clause (recall 1.0), precision@5 0.014. Diagnosis for both: chunk length ≈ 4–14× gold length; this is the main limitation (§7).

**E. False abstention on answerable queries (3)**
11. `cuad-5f26f5e6ab` (train) — Glu Mobile Amendment No. 3, "expiration date?" (confidence 0.227 < 0.68). Gold says "shall expire on December 31, 2006"; the literal question word "expiration" is not in the text.
12. `cuad-343d64c560` (train) — Jaguars/ARC "what licenses are granted?" (0.565). Gold is a long grant clause (1697–2488) whose vocabulary is not concentrated around the question words.
13. `cuad-39806369ca` (train) — Theravance "expiration date?" (0.514). Gold: employment "will commence ... and shall continue". Diagnosis for all three: peakedness uses the *unexpanded* question, so clauses that answer in other words look unsupported — retrieval (with expansion) would have ranked them, abstention discards them.

**F. False acceptance on unanswerable queries (3)**
14. `unans-003` — "Does Cano Petroleum have an option to renew ... for 2009?" (0.712). The agreement's heading "9. Term and Renewal" matches the word "renewal" although the text grants no option — a deliberately plausible question.
15. `unans-015` — "Does the GE Capital agency agreement with Duckwall-Alco require disputes to be submitted to arbitration?" (0.861). Contract names plus "agreement"/"dispute" generate a literal peak at the signature/instructions block.
16. `unans-016` — "Which party guarantees Duckwall-Alco's payment obligations...?" (0.828). Same name-driven peak.

Also observed interactively through the Streamlit app: the governing-law question for the Cano agreement (which does contain §11 Governing Law) was abstained at confidence 0.640 < 0.68 — another false abstention, outside the saved evaluation.

## 7. Limitations and next steps

* **Precision.** Five 1500-char passages vs ~400-char gold: P@5 ≈ 0.05. Next: passage re-segmentation to sentence/clause level after chunk retrieval, restrict the top-k to the routed contract (not tried), a reranker or dense model (not tried), and a longer-form precision-aware objective.
* **Cross-references and definitions.** 41/140 train and 22/54 test queries have gold text containing references ("Section …", "as defined", "hereof"); retrieval does not follow them. Several indexed contracts incorporate other documents (leases, ordinances, SPAs) that are not in the corpus.
* **Benchmark shape.** Every benchmark query names its contract and is one of ~30 CUAD templates; real users ask free-form questions about unknown contracts. Document routing was solved "for free" in the baseline and partly un-solved in the final config (doc hit@5 ≈ 0.82); the lexicon and thresholds may not transfer.
* **Abstention.** Train-fitted threshold (0.68) with a 10% false-abstention budget. The unanswerable questions are free-form while answerable ones are templated, so the peakedness signal may partly detect *query form*; I mitigated by stripping the "Consider …" prefix but cannot rule this out. Only 6 test unanswerable queries.
* **Unanswerable-set verification.** 17 items (Cano ×4, RGC ×3, Glu amendment ×2, Veoneer ×4, ALCO ×4) were verified by reading the whole contract plus regex absence checks. The other 22 (Arc Group, Flotek, Holiday RV, Union Dental, Western Copper, PC Quote, Theravance, Healthcare Integrated, Loop) were verified by regex absence checks and reading the paragraph/section structure and keyword contexts, **not** by reading every line; some rationale strings in the frozen file say "structural read" where that is all that was done. Some contracts incorporate documents that are not indexed (noted in rationales). A human lawyer has not reviewed the set. The file was left unchanged because it is frozen.
* **Small data.** 29 contracts; test n=54; differences of a few points are noise (e.g. the +0.0026 RRF gain accepted at iteration 7 is within noise).
* **Stemmer.** Home-grown suffix stripping is crude (see failure 3); a proper stemmer or lemmatiser is untested.
* **Not production-ready for legal users.** It returns candidate evidence, does not interpret it, has no clause-level guarantees, and has not been evaluated on other contract types or by legal reviewers.

## 8. Privacy and security

No contract text leaves the machine: no hosted model, embedding API or telemetry is used (the only network use is the one-time dataset download from Hugging Face). Had a hosted LLM been added,
contract text would be sent to a third party; the design therefore keeps any such step optional, cached and off by default. Contracts, queries and retrieved passages are treated as untrusted data and
never interpreted as instructions (nothing in the pipeline executes or follows text from documents). No secrets exist in the repo; `.env.example` holds placeholders only; `data/raw/`, caches and PDFs are git-ignored.

## 9. Reproducibility

```bash
pip install -e ".[data,app,dev]" && contract-intel setup
contract-intel evaluate --split train --config configs/baseline.yaml
contract-intel evaluate --split train --config configs/final.yaml
contract-intel optimize --config configs/baseline.yaml --iterations 10     # appends a new run to the log; ~35 s
contract-intel evaluate --split test --final --config configs/final.yaml   # logged as an additional test run
pytest                                                                       # 194 passed (3 need data/raw)
```
Environment used: Python 3.12.0, Windows 11; dependencies PyYAML (core), pytest, ruff, streamlit, huggingface_hub. Config hashes: baseline `d3989b03f063`, final `1cec43a77086`; manifest `e2a5024fd7e7ef0b`.
Git history documents the order: unanswerable set + objective (`f5b73f4`), objective revisions before each run (rev 1.1–1.4), freeze tag `config-frozen`, then test runs.
Test-suite status at the end of this work: `pytest` → **194 passed** (`-m "not data"` → 191 passed; `-m data` → 3 passed); `ruff check src tests` clean; Streamlit `AppTest` boots and handles result, abstention and empty-query paths.
